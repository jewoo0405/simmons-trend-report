## 0. 작업 전 필수 사항

### 0-1. 먼저 코드베이스를 파악할 것

이 지시서는 리포트 **산출물(HTML/PDF)** 을 보고 작성되었다. 실제 소스 구조는 확인되지 않았으므로,
수정에 착수하기 전에 아래를 먼저 조사하고 결과를 보고하라.

- [ ] 데이터 수집 모듈 (Google Trends / Naver API 호출부)
- [ ] 지표 산출 모듈 (SoS, SoM, Gap, CV 계산부)
- [ ] 렌더링 모듈 (HTML 템플릿, 차트 설정)
- [ ] 브랜드 메타데이터 정의 위치 (티어, 키워드, 매출 데이터)
- [ ] 원본 수집 데이터의 저장 형태 (raw JSON/CSV 존재 여부)

**원본 수집 데이터가 보존되어 있지 않다면 그 사실을 먼저 알릴 것.**
재수집 없이는 P0 과제 대부분을 검증할 수 없다.

### 0-2. 절대 규칙

1. **데이터를 임의로 만들어내지 말 것.** 값이 없으면 `null`로 두고 UI에서 "데이터 없음"으로 표기한다.
   추정치를 넣어야 한다면 반드시 별도 표기하고 근거를 남긴다.
2. **기존 산출 로직을 지우지 말고 병기하라.** 기존 정의를 바꾸는 과제(P1-1 등)는
   기존 값을 남긴 채 신규 값을 추가하는 방식으로 구현한다. 시계열 연속성이 깨지면 안 된다.
3. **각 과제마다 커밋을 분리하라.** 커밋 메시지에 과제 번호를 포함한다. (예: `fix(P0-1): 미완결 월 감지 로직 추가`)
4. **수정 후 반드시 리포트를 재생성하여 검증 조건을 직접 확인하라.** 코드만 고치고 끝내지 않는다.

### P0-1. 미완결 월 데이터 경고 처리

**현상**

1. 수집일이 해당 월의 마지막 날이 아니면 `is_partial_month = True` 플래그를 세운다.
2. 부분 집계 월은:

3. 리포트 최상단에 경고 배너 추가:
   `※ 2026년 8월은 1~19일 부분 집계 데이터입니다. 전월비 증감률 해석에 주의하십시오.`
4. '이번 달 변화점' 섹션은 부분 집계 월일 경우 **직전 완결 월(7월) 기준으로 대체 산출**하고

**검증**

### P0-2. Google Trends 배치 정규화 재설계 ★최우선

**현상**
5페이지 각주에 시스템이 스스로 띄운 경고가 있다:
`⚠ 결측/편차: 배치C max/min=251.6x > 20 (배치 재구성 권장)`

한 배치 안에서 최대·최소 검색량이 251배 차이 나면 Google Trends 정규화 특성상
하위 브랜드가 0~1 구간으로 뭉개진다. 실제로 4페이지 원본값 컬럼이 이를 증명한다:

| 브랜드 | 원본값 | 표시 지수 | 문제 |
|---|---|---|---|
| 씰리침대 | 0.4 | 3.4 | 반올림 오차만 ±12% 이상 — 허위 정밀도 |
| 코웨이 비렉스 | 0.0 | 0.1 | 측정 해상도 미달. "검색 없음"이 아님 |
| 현대리바트 | 1.5 | 14.0 | 유효숫자 2자리로 소수 첫째 자리까지 표기 |

**수정**
1. **체인 정규화(chained normalization)로 전환한다.**
   - 브랜드를 검색량 규모별로 그룹핑한다 (예: 대형 = 이케아·한샘 / 중형 = 시몬스·일룸·까사미아 / 소형 = 지누스·에이스침대·에몬스·현대리바트·씰리침대·코웨이 비렉스)
   - **모든 배치에 공통 앵커 브랜드(시몬스)를 반드시 포함**시킨다
   - 각 배치를 앵커 기준으로 재스케일한 뒤 결합한다
2. 배치 구성 후 `max/min` 비율을 재계산하여 **모든 배치가 20배 이하**가 되도록 한다.
   달성 불가한 브랜드는 별도 배치 + 주석 처리.
3. **유효숫자 규칙 도입:** 원본값 < 1.0 인 브랜드는 지수를 소수점 없이 표기하고
   `※ 측정 해상도 한계 (원본값 < 1)` 주석을 단다.
4. 배치 구성 결과를 리포트 부록에 표로 노출한다 (배치명 / 포함 브랜드 / max-min 비율 / 앵커).

**검증**
- [ ] 배치 경고 메시지가 사라진다
- [ ] 씰리침대·코웨이 비렉스 지수가 재수집 전후로 어떻게 바뀌는지 로그로 비교 출력
- [ ] 앵커(시몬스) 값이 모든 배치에서 일관되게 100으로 수렴하는지 확인

## P1 — 지표 정의 오류

### P1-1. SoS 분모 이원화 (전체 기준 / 카테고리 기준 병기) ★영향 최대

**현상**
SoS 분모가 11개 브랜드 전체 합계다. 이케아 57.8% + 한샘 17.5%만으로 분모의 75%를 차지하며,
일룸·까사미아·현대리바트·에몬스를 더하면 종합가구 브랜드가 분모의 대부분을 점유한다.
그 결과 시몬스 SoS가 **8.1%로 실제 카테고리 내 위상보다 크게 낮게 표시**된다.

**수정**
브랜드 메타데이터에 `category` 필드를 추가하고 (`bed_specialist` / `general_furniture`),
SoS를 **두 가지 기준으로 동시 산출**한다.

```
SoS_total      = 브랜드 검색량 ÷ 11개 브랜드 합계 × 100   (기존 유지)
SoS_category   = 브랜드 검색량 ÷ 침대 전업 브랜드 합계 × 100   (신규)
```

침대 전업 = 시몬스, 에이스침대, 씰리침대, 지누스 (4개)

> **주의:** 반올림된 SoS 값이 아니라 **원본 지수값으로 재계산**할 것.
> 현재 데이터 기준 시몬스의 카테고리 SoS는 약 57% 수준으로 예상되나, 반드시 코드로 산출한 값을 사용한다.

UI에서는 카테고리 기준을 **주(主) 지표**로, 전체 기준을 보조로 표시한다.

**검증**
- [ ] 카테고리 기준 4개 브랜드 SoS 합이 100%가 된다
- [ ] KPI 카드에 두 기준이 병기된다
- [ ] 기존 `SoS_total` 값이 그대로 보존되어 시계열이 끊기지 않는다

### P1-2. 구글 vs 네이버 Gap 지표 재정의

**현상**
`Gap = 네이버 지수 − 구글 지수` 로 산출하고 있으나, **두 지표는 차원이 다르다.**

- 구글 카테고리 지수 = 검색 **수요** (소비자가 얼마나 찾는가)
- 네이버 카테고리 지수 = 콘텐츠 **공급** (블로그·뉴스가 얼마나 발행되었는가)

리포트 4페이지가 스스로 `⚠ 검색 수요가 아닌 콘텐츠 발행량 지표. 브랜드 자체 마케팅 물량에 직접 좌우됨`
이라고 경고해놓고, 3페이지에서 그 값을 구글 수요 지표와 빼고 있다. 수요와 공급의 차이는 해석 불가능하다.

**수정 — 아래 둘 중 하나를 선택하고, 선택 근거를 보고할 것**

**옵션 A (권장):** 네이버 측 데이터 소스를 **DataLab 검색량**으로 교체
→ 수요 대 수요 비교가 되어 뺄셈이 성립한다. 진짜 "플랫폼별 검색 수요 분포"를 볼 수 있다.
→ 6페이지 성별·연령대 차트에서 이미 DataLab을 사용 중이므로 인증·연동은 확보된 상태다.

**옵션 B:** 현재 데이터를 유지하되 지표를 나눗셈으로 재정의
```
콘텐츠 생산성 = 네이버 콘텐츠 건수 ÷ 구글 검색 지수
```
→ "검색 1단위당 콘텐츠가 얼마나 붙어 있는가" = 마케팅 물량 집중도 지표
→ 섹션 제목을 `구글 vs 네이버 갭 분석` → `검색 수요 대비 콘텐츠 발행량`으로 변경

**동시 수정 (어느 옵션이든)**
- '주요 발견'의 `시몬스는 네이버에서 구글보다 78.2pt 높음 → 네이버 강세` 문구를 삭제 또는 재작성.
  에이스침대가 +163.3으로 시몬스 +78.2의 2배 이상이므로 **'강세'라는 표현 자체가 성립하지 않는다.**

**검증**
- [ ] 지표 정의와 산출식이 일치한다
- [ ] '네이버 강세' 문구가 데이터와 모순되지 않는다

### P1-3. 시몬스 SoM 산출 (현재 "산출 불가"로 표기됨)

**현상**
ESOV 차트에 `🚩 시몬스 SoS: 8.1% · SoM 산출 불가 (비상장 — DART 공시 없음)` 이라고 표기되어 있으나
**이는 사실이 아니다.**

시몬스는 비상장이지만 **외부감사 대상 법인이므로 감사보고서가 DART에 공시된다.**
매년 3월 언론이 이 자료를 근거로 실적을 보도한다.

**확인된 실적 (재검증 필수)**

| 연도 | 시몬스 | 에이스침대 |
|---|---|---|
| 2023 | 3,138억 | 3,064억 |
| 2024 | 3,295억 | 3,260억 |
| 2025 | 3,239억 | 3,173억 (연결) |

**수정**
1. DART Open API로 시몬스(주) 감사보고서 매출액을 수집하도록 파이프라인을 추가한다.
   → API 연동이 어려우면 수동 입력 + 출처·기준일 명시로 우선 처리
2. `SoM 산출 불가` 경고 박스를 제거하고 시몬스를 ESOV 차트에 실제로 플로팅한다.
3. **분모 정의를 SoS와 일치시킨다.** (P1-1과 연동)

     분자·분모의 지역 정의가 어긋나므로, 국내 매출 분리가 불가능하면 **ESOV 차트에서 제외**하거나
     `※ 글로벌 매출 기준 — SoS(국내)와 지역 범위 불일치` 주석을 반드시 단다.
4. 비상장 브랜드는 `data_source: DART_audit_report` 로 태깅하고 결산 기준일을 각주에 표기한다.

- [ ] 매출 수치의 출처와 기준연도가 각주에 명시된다
- [ ] SoS 분모와 SoM 분모의 브랜드 구성이 일치한다

### P1-4. ESOV 대각선 해석 방향 수정 + 참조선 추가

**현상 1 — 해석 오류**
7페이지 가이드에 `아래쪽 = 검색 대비 매출 적음 (전환 효율 점검 필요)` 라고 되어 있다.
그러나 Binet & Field의 원 ESOV 이론에서 **SoV > SoM(양의 ESOV)은 미래 점유율 성장의 선행지표**다.
부정 신호가 아니라 축적된 브랜드 자산에 가깝다. 광고 중심 브랜딩을 해온 시몬스에는 특히 중요한 차이다.

**수정 1**
```
아래쪽(SoS > SoM) : 양(+)의 ESOV — 점유율 성장 여력 · 브랜드 자산 선행 축적
위쪽(SoS < SoM)   : 음(−)의 ESOV — 검색 점유 열위 · 브랜드 투자 필요
```

**현상 2 — 참조선 부재**
가이드는 대각선(y=x)을 기준으로 설명하는데, **차트에 해당 선이 실제로 그려져 있지 않다.**

**수정 2**
`y = x` 대각선을 점선으로 렌더링하고 범례에 `SoS = SoM 기준선`으로 표기한다.

**검증**
- [ ] 차트에 대각선이 보인다
- [ ] 해석 가이드 문구가 ESOV 이론과 일치한다

### P1-5. SoS 목표치 재설정 (권고 액션)

**현상**
권고 액션에 `Share of Search 10% 목표 설정 (현재 8.1%)` 이 있다.
현재 분모 구성에서 10%를 달성하려면 사실상 **이케아 검색량이 감소해야 한다.**
자사가 통제할 수 없는 변수에 KPI가 걸려 있다.

**수정**

```
      · 보조지표: 전체 기준 SoS 8.1% 유지 이상
```
※ 정확한 현재값은 P1-1 산출 결과로 대체할 것.

### P2-2. 연령대 수치 불일치

**현상**
권고 액션: `20-30대 검색 비중 제고 (현재 24.0%, 에이스침대 대비 저조)`
6페이지 실측: 시몬스 20대 **4.7%** + 30대 **17.6%** = **22.3%**
(10대 2%를 포함하면 24.3%이나, 그것은 '20-30대'가 아니다)

**수정**
1. 산출 범위를 코드에서 확인하여 `22.3%`로 정정하거나, 24.0%의 근거를 명시한다.
2. 비교 대상 수치도 함께 표기한다. (에이스침대 20대 17.1% + 30대 18.4% = 35.5%)
3. 액션 문구 예시:
   `20-30대 검색 비중 제고 (시몬스 22.3% vs 에이스침대 35.5%)`

**검증**
- [ ] 권고 액션의 수치가 6페이지 차트와 정확히 일치한다

### P2-3. '주요 발견' 생성 규칙 수정

**현상**
```
· 구글 1위 이케아 집중 모니터링 필요
· 네이버 1위 이케아 집중 모니터링 필요
```
두 줄이 사실상 중복이며, 이케아는 **Tier C(종합가구)로 직접 경쟁자가 아니다.**
룰이 단순히 '1위 브랜드'를 뽑도록 되어 있는 것으로 보인다.

**수정**
1. 모니터링 대상을 **Tier A·B(에이스침대·씰리침대)로 한정**한다.
2. Tier C 브랜드는 `참고: 카테고리 전체 1위는 이케아(종합가구)` 형태의 보조 문구로 강등한다.
3. 동일 대상에 대한 중복 발견은 하나로 병합한다.

**검증**
- [ ] '주요 발견'에 중복 항목이 없다
- [ ] 경쟁 모니터링 대상이 직접 경쟁군으로 설정된다

### P2-4. 히트맵 노이즈 억제

**현상**
- 현대리바트 26.01 `+364.2%` — 원본값 6.7 → 31.1에서 발생한 값. 저기저 구간의 %는 노이즈 증폭이다
- 씰리침대의 `0.0`과 `—`(데이터 없음)이 시각적으로 구분되지 않는다
- 26.04 `-100.0%`, 26.05 `—` 등 결측 처리가 일관되지 않다

**수정**
1. 원본 지수 < 10 구간의 증감률은 **회색 처리 + 배경색 제거** (강조하지 않음)
2. `0.0` (측정됨, 값 없음) 과 `—` (미수집) 을 서로 다른 스타일로 구분하고 범례 추가
3. 증감률 색상 스케일에 상한을 둔다 (예: ±100% 클리핑) — 364%가 스케일 전체를 지배하지 않도록

### P3-3. CV 산출 방식 개선

현재 CV는 추세와 노이즈를 구분하지 못한다. 12개월 내내 우상향한 브랜드와
평균은 같은데 매달 널뛰는 브랜드가 동일한 CV를 받는다.

```
개선안: 3개월 이동평균으로 추세 제거 → 잔차 기준으로 CV 재산출
표기:   CV_raw (전체 변동) / CV_detrended (순수 노이즈) 병기
```

또한 CV 산출 기간이 12개월이면 계절 주기가 1회뿐이라 계절성과 추세를 분리할 수 없다.
가능하면 24개월 이상으로 확대를 검토하라.

## 작업 순서

```
1. [조사]  0-1 코드베이스 파악 → 결과 보고 후 승인 대기
2. [P0]    P0-2 배치 정규화  ← 여기서 나온 값이 이후 전부에 영향
           P0-1 미완결 월, P0-3 비렉스 정합성
3. [검증]  리포트 재생성 → P0 검증 항목 확인 → 값 변화 보고
4. [P1]    P1-1 분모 이원화 → P1-3 시몬스 SoM → P1-4 ESOV → P1-5 목표
           P1-2 Gap 재정의 (옵션 선택 승인 후 착수)
5. [P2]    라벨·표기 일괄 수정
6. [최종]  전체 재생성 → 전 검증 항목 점검 → 변경 요약 리포트 작성
```

**P0-2 완료 시점에 한 번 멈추고 값 변화를 보고하라.**
